Deviations from the spec

  • Purchase opens the Manifold collection page, the same for every piece, and is in the menu before a piece is opened. The spec said the open piece's marketplace page; your B5 note asked for this instead.

Elevated decisions

B1 asked for the thumbnail to load only if the engine fails, but the engine loads the thumbnail itself as its base frame, and the imagein only after it.

Options: load the thumbnail only on failure (blocks the engine); mark the fallback fetchpriority="low" as Sk3tch does (slows the engine's base frame, since it shares the download); start both engine images in <head>.

Chose: start both at page load, fallback untouched (as amended by B2 below). This relaxes the plan's rule that only the three image URLs change in the vendored pages; engine bytes are untouched.

Reverse: delete the two added <head> lines in each page and the B1 test.

B2: B1's <link rel="preload" as="fetch" crossorigin> for the imagein made the engine's own fetch fail with "Failed to fetch" once the file was cached, so a piece showed its still and never moved.

Options: drop the imagein preload (the engine fetches it only after the thumbnail, about 2.5s slower cold in one test run); a preload without crossorigin (Chrome doesn't use it, "credentials mode does not match", so the file would download twice); a plain fetch() in <head>.

Chose: <script>fetch("<imagein>").catch(() => {})</script> in each page's <head>. It uses the same request mode as the engine's fetch, so the engine reuses it. In a cold run, both requests finished at the same moment. This adds a new one-line script to each vendored page; the existing scripts and engine bytes are untouched.

Reverse: delete that line in each page (the imagein then loads after the thumbnail).
